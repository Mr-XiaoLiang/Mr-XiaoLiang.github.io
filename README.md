# MrUserPage

Windows 8 风格的静态个人主页。部署于 GitHub UserPage，全部个性化数据保存在浏览器本地，无后端。

## Metro 风格要求（铁律 · 最高优先级）

本项目所有界面——桌面磁块、内置小组件、应用库、设置等浮层——必须无条件遵循
**Windows 8 / Windows Phone 8 Metro** 视觉语言。本条目是最高优先级，任何布局、配色、字号、
交互改动都不得违背，其后各章节均从属于本条目。

1. **直角、无圆角**：所有磁块、按钮、输入框、弹窗、色块一律 `border-radius: 0`，禁止任何圆角、胶囊、椭圆。
2. **扁平纯色、无质感**：纯色块填充，禁止渐变、阴影（仅拖拽悬浮等临时状态可例外）、模糊、描边光晕、玻璃拟态。
3. **纯黑/纯白底 + 高对比字**：深色方案纯黑底（`--flat-bg: #000`）配纯白字，浅色方案反之；禁止用降低文字透明度来弱化内容。
4. **单一强调色点缀**：只使用一个强调色（`--accent: #1ba1e2`），用于选中、焦点、主操作与「今日」等强调，不得多色混用、堆砌。
5. **内容优先、克制留白**：不靠缩小字号或降透明度「塞更多」内容；最小可读字号 11px 且必须不透明；宁可滚动、分页。
6. **字号阶梯（细体优先）**：页标题 27px 细体(300)、区块标题 24px(300)、正文 15px(400)、说明 12px(400)；大字号用轻字重是 Metro 的识别特征。
7. **动效克制**：浮层入场 250ms ease-out、退场 167ms ease-in，其余交互避免多余动画。

## 设计模型

### 屏与格

- 每一「屏」的宽度以「格」计量，最小 4 格、最大 8 格（设置中可调，默认 6）
- 格为 1:1 正方形，格尺寸由密度档（宽松 / 适中 / 紧凑）决定
- **单屏横向格数固定**：由设置决定（4-8），不随视口宽度变化；视口变窄时缩小格边长来容纳这固定的格数，已排布的内容不会因为变窄而被裁掉
- 真正随视口变化的是「屏」的排列：宽屏多屏并列，窄屏单屏串联（换行）；放不下下一屏的空间留空，不横向滚动；屏间距远大于格间距；纵向空间不限，上下滚动

#### 布局换算比例尺

所有间距以格边长 `cell` 为基准推导（`core/grid.ts`），磁贴方块紧贴成群、只在屏与屏之间分栏，对齐 Windows Phone 磁贴规范：

| 量 | 公式 | 宽松 (108) | 适中 (88) | 紧凑 (72) |
| --- | --- | --- | --- | --- |
| 格边长 `cell` | 基准 | 108px | 88px | 72px |
| 磁贴间隙 `gap` | `round(cell × 1/32)` | 3px | 3px | 2px |
| 屏间距 `screenGap` | `round(cell × 1/3)` | 36px | 29px | 24px |
| 左右边距 `paddingX` | `= screenGap` | 36px | 29px | 24px |

磁贴间隙约为格边长的 3%（细缝），屏间距约为格边长的 1/3（磁贴间隙的约 10 倍）。

### 磁块

- 最小 1x1，最大 4x4。合法尺寸共 12 档：1x1、1x2、2x1、2x2、2x3、3x2、2x4、4x2、3x3、3x4、4x3、4x4
- 应用图标默认 1x1；编辑态下拖拽磁块右下角手柄可调整尺寸（实时预览、松手吸附到合法尺寸）
- 双维均不小于 2 格时，磁块左下角展示名称；小组件的动态内容同样要求双维 ≥ 2 格
- 磁块为直角矩形，背景取应用自定义色或主题色板（按 id 稳定取色）
- 内容优先级：`live` 动态内容 > `fullIcon` 全覆盖图 > `icon` 图标；后两者与 live 互斥
- 布局自由排列但不跨屏：任一磁块必须完整落在一屏的横向范围内；屏内采用 dense 流自动排布，空行自然消除

### 交互

- 长按桌面空白处进入编辑模式：磁块可拖拽（屏内调序、跨屏移动）、右下角手柄调尺寸、左上角徽标取消固定 / 移除小组件
- 无 Dock，所有内容都是磁块
- 应用库磁块（默认 1x1，唯一不可删除）点击打开全屏应用库：顶部「应用 / 小组件」Tab；应用按名称首字母分组（拉丁字母 A-Z，其余归 #），点击分组标题弹出 26 字母宫格跳转；列表行为 1 格方形图标 + 名称，点击打开，未固定的应用可「固定到屏幕」
- 小组件 Tab 展示内置小组件、`Widgets.json` 网页小组件与用户自定义小组件，可选尺寸后添加；自定义小组件以 `.zip` 压缩包导入

## 预设文件

- `public/Apps.json`：预设应用。字段：`name`、`url`、`icon` 必填；`fullIcon`（全覆盖图）、`color`（磁块色）、`description`、`category` 可选
- `public/Widgets.json`：预设网页小组件。字段：`name`、`url` 必填；`icon`、`description` 可选

## 内置小组件

| 类型 | 说明 | 最小尺寸 |
| --- | --- | --- |
| clock | 数字时钟；横条（1 行高）仅显示时间，2 行及以上追加中文日期 | 2x1 |
| search | 多引擎搜索框（Bing / 百度 / Google / DuckDuckGo），可选默认引擎 | 2x2 |
| calendar | 当月月历，高亮今日 | 2x2 |
| iframe | 以沙箱 iframe 加载网页，附「新窗口打开」出口 | 2x2 |

新增内置小组件：在 `src/widgets/builtin/` 下新建一个符合协议的文件夹（`manifest.json` + 入口代码文件），并在 `src/widgets/builtin.ts` 补一行注册。

## 自定义小组件（zip 导入）

用户制作完成的小组件打包为 `.zip` 后，在「应用库 → 小组件 → 自定义小组件 → 导入小组件」中直接导入，即时生效。压缩包需包含 `manifest.json` 与入口文件 `index.js`（或 `index.mjs`），遵循与内置小组件相同的协议。入口文件是自包含 ES 模块，通过全局 `MrUserPageWidget` 获取 Vue 运行时与压缩包资源。

接入说明与完整示例见 `public/widget-docs.html`（部署后即 `https://…/widget-docs.html`），入口旁提供「接入说明」与「复制说明页链接」，可直接把该页链接发给 AI 代为编写小组件。

## 壁纸

设置中提供四个来源：内置渐变（5 套，带明暗标记）、在线图片 URL、本地上传（压缩至最长边 1920 像素后存入本地）、动态光晕（用户自选 3 色与流速，流动动画）。文字与玻璃配色自动跟随壁纸明暗，也可在设置中强制亮色 / 暗色。

## 数据

- 配置存储于 localStorage（键 `mruserspage:config`），含版本号；设置中可导出 JSON、导入校验、两步确认恢复默认
- 导入会校验配置版本与必要字段，不兼容时给出明确错误

## 开发

```bash
npm install
```

## 部署

push 到 `main` 即由 GitHub Actions 自动构建并发布到 GitHub Pages。要求：

1. 远端仓库名为 `<用户名>.github.io`（UserPage）
2. 仓库 Settings → Pages → Source 选择 GitHub Actions
3. 域名 DNS 添加 CNAME：`m` → `<用户名>.github.io`（自定义域名已配置为 m.looly.top）

## 目录结构

```
src/
├── core/          # 框架无关内核：类型、模型、持久化、预设、布局计算、搜索引擎、取色
│   ├── board.ts   # 棋盘布局引擎（纯函数）：坐标打包、碰撞、拖拽落点吸附解析
│   └── drag.ts    # 拖拽框架（响应式控制器）：指针捕获、1:1 跟手、落点高亮、边缘自动滚动
├── composables/   # useTheme（主题初始化）、useLayoutMetrics（格尺寸测量）、useWidgetDocs 等组合式函数
├── stores/        # Pinia 配置 store（唯一数据源）
├── features/
│   ├── desktop/   # DesktopView、ScreenGrid、Tile、编辑态、添加面板
│   ├── library/   # AppLibrary（Win8 双 Tab + 字母宫格）、LetterJump
│   ├── wallpaper/ # 壁纸层与动态光晕
│   └── settings/  # 设置面板（壁纸 / 布局 / 主题 / 数据）
├── widgets/       # 小组件协议、注册表、运行时、zip 加载器与内置小组件
public/
├── Apps.json / Widgets.json / CNAME
├── widget-docs.html # 小组件接入说明（独立静态页，可复制链接分享给 AI）
```

### 布局与拖拽框架

布局与拖拽是独立的两层，业务（应用 / 小组件）不参与其中：

- `core/board.ts` 纯函数引擎：磁块坐标打包（显式坐标优先，缺失者行优先补位）、
  碰撞检测、以及「指针 + 抓取偏移 → 目标屏 / 目标格」的吸附解析。
- `core/drag.ts` 拖拽控制器：`beginDrag` 后用指针捕获保证事件不中断，被拖磁块以
  `position: fixed + translate3d` 逐帧 1:1 跟手；落点通过各屏注册的实时矩形解析，
  以 `dragState.target` 响应式暴露给界面渲染高亮；靠近滚动容器上下边缘自动滚动。
- 存储态即渲染态：归一化时为每块磁块写入显式 `col/row`，保存压缩与碰撞检测
  不再依赖“缺坐标按 0,0 处理”的猜测。
- 业务接入点只有一处：拖拽结束回调里调用 `store.moveTileTo(id, screen, col, row)`。
